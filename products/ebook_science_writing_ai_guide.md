# 第1章 ── 科学ライティングの「鉄のルール」

## 1.1 なぜ「普通のライティング」では通用しないのか

ブログ記事やSNS投稿と科学ライティングの決定的な違い。それは**断定強度の管理**です。

一般的なライティングでは「〜です」「〜になります」で統一しても問題ありません。しかし科学ライティングでは、書いていることが「確定した事実」なのか「有力な仮説」なのか「筆者の推測」なのかを、一文単位で区別する必要があります。

これを怠ると何が起きるか。**嘘を書くことになる**のです。

## 1.2 断定強度チャート ── 三段階の使い分け

科学記事のすべての文は、以下の3レベルのいずれかに分類されます。

| レベル | 定義 | 使うべき表現 | 絶対NGな表現 | 使用条件 |
|:--|:--|:--|:--|:--|
| **Fact** | 検証された事実 | 「〜である」「〜と確認された」 | — | 一次資料＋交差検証済み |
| **Model** | 理解のための説明モデル | 「〜と考えられている」「例えると」 | 「〜である」 | 比喩やモデル。必ず「あくまで例えだが」を添える |
| **Hypothesis** | 推測・予想 | 「〜かもしれない」「筆者の見立てでは」 | 「〜は確実」 | 根拠を併記する |

**重要なのは方向性です。**

- Factを「〜かもしれない」と弱めるのは **誠実さの暴走** → 読者が混乱する
- Hypothesisを「〜である」と強めるのは **捏造** → 信頼が崩壊する

正確なものは正確に書く。不確実なものは不確実だと正直に書く。この規律こそが科学ライティングの土台です。

## 1.3 鉄のルール：「新しい事実を勝手に追加しない」

AIを使った科学ライティングで最もリスクが高いのは、**AIが「もっともらしい嘘」を生成すること**です。

ChatGPTやClaudeは膨大な知識を持っていますが、その知識がいつの時点のものか、どの程度正確かは保証されていません。「AIが言ったから正しい」は、科学ライティングでは通用しません。

だから鉄のルールを敷きます：

> **リサーチフェーズ以外で、新しい事実を追加してはならない。**

文章を「面白くしよう」として、AIが検証されていないデータや事例を追加することがあります。これは致命的です。出典不明の情報は、あなたの記事の信頼を根底から破壊します。

# 第2章 ── 「二層構造」で誰にでも伝わる科学記事を書く

## 2.1 直感→理屈の二段階構造

科学記事最大の課題は「正確さと分かりやすさの両立」です。

正確に書こうとすると専門用語だらけで読者が離脱する。分かりやすく書こうとすると不正確になる。このジレンマを解決するのが「二層構造」です。

すべての技術的な説明を、次の2段階で書きます：

**第1層：直感レイヤー（比喩・イメージ）**
→ これだけ読んでも大意がつかめる

**第2層：理屈レイヤー（正確な技術説明）**
→ ここまで読めば専門家にも通用する

## 2.2 実例で見る二層構造

### 例1：ヒートポンプの仕組み

> 【直感レイヤー】
> ヒートポンプは「逆向きの冷蔵庫」です。冷蔵庫が庫内の熱を外に捨てるのに対し、ヒートポンプは外気の熱を「汲み上げて」室内に運び込みます。0℃の外気からでも熱を取り出せる——にわかには信じがたいですが、これが物理法則なのです。
>
> 【理屈レイヤー】
> 冷媒がコンプレッサーで圧縮されると、蒸発温度が外気温より低い状態に制御されます。この温度差により、0℃の外気からでも冷媒へ熱が移動（蒸発吸熱）します。圧縮された高温・高圧の冷媒は室内側のコンデンサーで凝縮し、その際に吸熱分＋圧縮仕事分の熱を放出します。

### 例2：マイクロ波送電

> 【直感レイヤー】
> 宇宙から地上への送電は「見えない光のビーム」で行います。Wi-Fiと同じ電波を使いますが、レーザーのように一方向に集中させ、36,000km離れた地上の受信アンテナにピンポイントで届けます。
>
> 【理屈レイヤー】
> 2.45GHzまたは5.8GHz帯のマイクロ波を位相制御アレイアンテナから送信します。地上のレクテナ（Rectifying Antenna）でマイクロ波を整流し直流電力に変換。変換効率は理論上90%以上、システム全体（宇宙→地上）の伝送効率は50〜80%を目指した研究が進んでいます。

## 2.3 二層構造のルール

1. **直感レイヤーだけ読んでも記事として成立させる**
2. **理屈レイヤーは「もっと詳しく知りたい人」への特典**
3. **直感レイヤーでは「あくまで例え」であることを示唆する**
4. **理屈レイヤーの用語は初出で必ず補足する**
5. **記事上では【直感】【理屈】のラベルは使わず、自然に接続する**

# 第3章 ── 「脱AI文体」10のチェックポイント

AIが書いた文章は、なぜ「AIっぽい」と見抜かれるのか。それには明確なパターンがあります。このチャプターでは、AIの文章を「人間の声」に変える10のテクニックを解説します。

## 3.1 教科書感の排除

| ❌ AIが書きがち | ✅ 人間の声 |
|:--|:--|
| 「ペロブスカイト太陽電池について説明します」 | 「あなたの家の屋根に、絵の具みたいに塗れる太陽電池があるとしたら？」 |
| 「以下の3点が重要です」 | 「ここ、テストに出ますよ（冗談ですが、本当に大事です）」 |

**核心**: 読者は「情報」を求めているのではない。**「体験」**を求めている。

## 3.2 リズムの変化

AIは「〜です。〜です。〜です。」と同じリズムで書く癖があります。人間の文章にはリズムの揺れがある。

```
❌ AIリズム:
この技術は革新的です。多くの研究者が注目しています。
今後の発展が期待されます。

✅ 人間リズム:
この技術は、率直に言って、ゲームチェンジャーだ。
なぜか？ 従来の常識を3つ同時にひっくり返すからである。
…少なくとも、論文のデータが正しければ。
```

## 3.3 感情の注入

| ❌ 無感情 | ✅ 感情あり |
|:--|:--|
| 「興味深い結果が得られました」 | 「正直、この数字を見たとき鳥肌が立った」 |
| 「予想外の発見がありました」 | 「え、待って。これ、大発見じゃないか？」 |

## 3.4 会話的な調子

| ❌ 論文調 | ✅ 語りかけ |
|:--|:--|
| 「次に述べる要因が影響する」 | 「ここがミソなんですが」 |
| 「前述のとおり」 | 「さっき言った話、覚えてますか？」 |

## 3.5 共感の獲得

| ❌ 上から目線 | ✅ 寄り添い |
|:--|:--|
| 「多くの人は知りません」 | 「あなたもそう思ってませんでした？ 私もです」 |

## 3.6 具体的な比喩

| ❌ 抽象 | ✅ 具体 |
|:--|:--|
| 「非常に大きなエネルギー」 | 「東京ドーム3個分のCO2が、たった1年で…」 |
| 「微小なスケール」 | 「髪の毛の太さの3倍。それが0.3mmの世界です」 |

## 3.7 思考プロセスの露出

```
❌ 結論だけ:
SSPSのコストは打ち上げ費に依存する。

✅ 思考プロセスあり:
最初、技術的な課題が最大のボトルネックだと思っていた。
ところが調べてみると、問題はもっとシンプルだった。
「いくらかかるか」——結局、お金の話なのだ。
```

## 3.8 中立病の打破

| ❌ 中立病 | ✅ ポジションを取る |
|:--|:--|
| 「一長一短があります」 | 「率直に言って、これは危うい」 |
| 「今後の研究が待たれます」 | 「もし5年以内に実証できなければ、この技術は終わる」 |

## 3.9 語尾バリエーション

```
❌ 語尾の三連続（AIの典型パターン）:
〜です。〜です。〜です。

✅ バリエーション:
〜だ。〜である。…なのだ、これが。
〜だろうか？ いや、〜なのかもしれない。
```

## 3.10 最後の問い

| ❌ 締め方 | ✅ 余韻を残す |
|:--|:--|
| 「以上です」「参考になれば幸いです」 | 「10年後、あなたはまだGPUを使っているだろうか？」 |
| 「まとめると〜」 | 「今夜、空を見上げたら——あの星々の間に、未来の発電所が浮かんでいることを想像してみてください」 |

# 第4章 ── AIを使った記事制作パイプライン

ここからが本書のメインディッシュです。AIを科学ライティングに**安全に、効果的に**組み込む全プロセスを解説します。

## 4.1 パイプライン全体像

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ テーマ発掘 │ → │ 深掘調査  │ → │ 記事執筆  │ → │ 投稿最適化 │
│Theme Forge│    │Research   │    │Story Forge│    │Post Forge │
│人間7:AI3  │    │人間4:AI6  │    │人間5:AI5  │    │人間3:AI7  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘

全工程: 約30分（従来: 2〜3時間）
```

## 4.2 Phase 1: テーマ発掘（Theme Forge）

**目的**: 「へぇ」ではなく「えっ、マジで？」を引き出すテーマを見つける。

**3つのカテゴリから均等に候補を出す**：
- 🔍 **日常の謎**: 当たり前を「なぜ？」に変える（空が青い、ゴムが伸びる）
- 🔧 **テック深掘り**: バズワードの中身を解剖する（GPU、量子もつれ）
- ⚖️ **社会×科学**: 噂や俗説を科学で検証する（添加物、5G）

**AIへの指示例**:

```
以下の条件でテーマ候補を10件提案してください：

1. ターゲット読者: 科学に興味があるが専門家ではない一般人
2. カテゴリ: 日常の謎(3件)、テック深掘り(4件)、社会×科学(3件)
3. 各テーマに以下を添えて:
   - 一行Hook（読者の「えっ？」を引き出す一文）
   - よくある誤解（覆すべき常識）
   - 図解にしやすいか（Yes/No）
4. 過去に扱ったテーマ: [リスト]
```

**人間の仕事**: AIの候補を5軸（新規性・需要・図解可能性・出典の入手性・SNS拡散力）でスコアリングし、上位3件を選ぶ。

## 4.3 Phase 2: 深掘り調査（Research Forge）

**目的**: テーマについて一次資料ベースの「Evidence Pack（証拠パック）」を作成する。

> ⚠️ **鉄のルール**: 新しい事実はこのフェーズでしか追加できない。

**Evidence Packの構成**:

1. **要点3行**（Factのみ）
2. **用語辞書**（初心者向けの噛み砕いた説明）
3. **仕組みの流れ**（コンセプトマップ）
4. **誤解ポイント**（よくある誤解 → 正確な理解）
5. **数値・条件**（値＋単位＋前提条件＋出典）
6. **限界・例外**（成り立たないケース）
7. **Hook候補**（5パターン以上）
8. **比喩候補**（限界も明記）
9. **出典テーブル**（一次/二次/三次の信頼度ラベル付き）

**AIへの指示例**:

```
テーマ「宇宙太陽光発電（SSPS）」について、Evidence Packを作成してください。

条件：
- 一次資料（論文、JAXA/NASA/ESA公式、政府報告書）を優先
- 重要な主張は2ソース以上で交差検証
- 全情報にFact / Model / Hypothesisラベルを付与
- 数値には必ず単位と前提条件を明記
```

**人間の仕事**: AIが出してきた出典を**必ず確認する**。URLを開いて、その情報が本当に書いてあるか検証する。

## 4.4 Phase 3: 記事執筆（Story Forge）

**目的**: Evidence Packを「Newton/NatGeo風の読者体験」に変換する。

**記事骨格（Story Spine）**:

| パート | 字数目安 | 役割 |
|:--|:--|:--|
| **Hook** | 400字 | 読者の常識を揺さぶる |
| **なぜ？** | 500字 | 構造的原因をえぐる |
| **仕組み** | 600字 | 技術メカニズム。二層構造必須 |
| **証拠** | 300字 | 数値データ。「翻訳」必須 |
| **未来** | 400字 | So What? ＋ 読者への問い |

**AIへの指示例**:

```
以下のEvidence Packから、ST Channel向けの科学記事を書いてください。

ルール：
- Story Spine（Hook→なぜ→仕組み→証拠→未来）に従う
- 二層構造（直感→理屈）で技術説明
- EPにない情報は絶対に追加しない
- 脱AI文体10ポイントを遵守
- 断定強度チャートに従う

[ここにEvidence Packを貼る]
```

**人間の仕事**: AIの出力を以下の品質ゲートで検査する。

### 品質ゲートチェックリスト

- [ ] EPにない新主張を追加していないか？
- [ ] Factに出典URLがあるか？
- [ ] 数値に単位・前提条件があるか？
- [ ] NG ワード（後述）を使っていないか？
- [ ] 同じ語尾が3回連続していないか？
- [ ] 二層構造が適用されているか？
- [ ] Hook は「えっ？」を引き出すか？

## 4.5 Phase 4: SNS投稿最適化（Post Forge）

**目的**: 記事を「壊さず圧縮」し、Xアルゴリズムのスコアを最大化する投稿文に変換する。

**Xアルゴリズムの重み付け**（いいね＝1x基準）:

| アクション | 重み | 戦略 |
|:--|:--|:--|
| リプライのリプライ（会話） | ×75 | 二択の問いで締めて会話を誘発 |
| リプライ | ×27 | 「あなたはどう思いますか？」 |
| RT | ×20 | 共有したくなるデータを入れる |
| ブックマーク | ×10 | チートシート形式で保存欲を刺激 |
| いいね | ×1 | 基本指標 |

**7つの鉄則**:

1. **会話を設計する**: 二択の問いで締め、リプライ×27〜75を狙う
2. **スレッドで滞在時間を稼ぐ**: 5-8ツイートで2分超の滞在時間
3. **事実の弾丸**: 共有したくなる衝撃データでRT×20を誘発
4. **保存知識**: チートシートでブックマーク×10を狙う
5. **リンク分離**: 外部URLはリプ欄へ（本文に入れるとリーチ-50〜90%）
6. **メディア添付**: 図解・動画で大幅ブースト
7. **初速最大化**: 朝7-8時 / 昼12-13時 / 夜20-22時に投稿

# 第5章 ── Hook（書き出し）生成パターン集

読まれるかどうかの80%は、最初の一文で決まります。

## 6つのHookパターン

| # | パターン | 構造 | 例 |
|:--|:--|:--|:--|
| A | **数値衝撃** | 「○○が△△%」 | 「年間3,300万トン。日本の食品ロスはフランスの国家予算に匹敵する」 |
| B | **逆説** | 「皆○○だと思ってるけど実は△△」 | 「空が青いのはレイリー散乱のせい…ではない、という話」 |
| C | **質問** | 「なぜ○○なのに△△？」 | 「なぜ氷は水に浮くのか？ 答えは、水が『変な液体』だから」 |
| D | **断言** | 「○○は終わった」 | 「ムーアの法則は死んだ。ただし、後継者がいる」 |
| E | **比喩** | 「○○は△△界の□□だ」 | 「量子コンピュータは、計算機界のパラレルワールドだ」 |
| F | **告白** | 「正直、〜ゾッとした」 | 「正直、この論文のFigure 3を見た時、背筋が凍った」 |

**使い分けのコツ**:
- **新しい研究** → A（数値衝撃）or F（告白）
- **日常の疑問** → C（質問）or B（逆説）
- **トレンド技術** → D（断言）or E（比喩）

# 第6章 ── 数値の翻訳テクニック

科学記事に数値は不可欠ですが、生のデータは読者に刺さりません。

## 翻訳ルール

| 翻訳前 | → | 翻訳後 |
|:--|:--|:--|
| 3,300トンのメタン | → | 東京ドームX杯分のCO2に相当 |
| 処理速度1.2 TFLOPS | → | 1秒間に1.2兆回の計算 |
| 0.3mmの精度 | → | 髪の毛の太さの3倍 |
| 36,000kmの軌道 | → | 東京〜シドニーの約4.5往復 |
| 設備利用率15% | → | パネルが持つ能力の6分の1だけ稼働 |

## 鉄則

1. **元の数値＋単位＋条件は必ず残す**（翻訳は「補足」として添える）
2. **条件（いつ、どこで、誰が測定）を省略しない**
3. **翻訳先は読者の日常にあるもの**（東京ドーム、髪の毛、スマホの充電回数）

# 第7章 ── NGワード完全リスト

科学記事の信頼性を破壊する言葉を3カテゴリに分類しました。

## 煽り系（信頼を毀損する）

```
画期的な / 注目の / 話題の / 衝撃の / ついに / いよいよ
驚愕の / 必見 / 神○○ / 最強の / 究極の
```

これらの言葉は「書き手の興奮」を表現しますが、科学記事では**データに語らせる**のが正解です。「画期的な発見」と書く代わりに、「従来の3倍の効率」と書けば、読者自身が「画期的だ」と判断します。

## YouTuber系（ブランド毀損）

```
〜してみた / 〜がヤバすぎる / 〜が凄すぎた / 〜した結果
〜ランキングTOP10 / 〇〇選
```

## AI文体バレ系（読者が離脱する）

```
いかがでしたか？ / まとめ / 参考になれば幸いです
それでは / 以上となります / 〜について説明します
重要なことは〜 / 特筆すべきは〜 / 注目すべきは〜
```

この3番目のカテゴリが最も危険です。読者が「これAIが書いたな」と感じた瞬間、記事の内容に関係なく信頼はゼロになります。

## 「天気予報を気にしない発電 ― 宇宙太陽光発電の現在地」

**← Hook: パターンB（逆説）×C（質問）の変形。「天気予報を気にしない」で常識を覆す**

「太陽光発電の弱点は？」

答えは簡単です。**夜は発電できない。雨が降ってもダメ。曇りでも効率がガタ落ちする。**

日本の太陽光発電の**設備利用率（稼働率）は約15%**。つまり、パネルが持つ最大能力のうち、実際に使えているのは6分の1だけ。残りの5/6の時間、パネルは「寝ている」のです。

**← 数値の翻訳: 「15%」→「6分の1」→「寝ている」。抽象→具体→比喩の三段階**

なら、いっそ「雲の上」に行ってしまえばいい。
いや、もっと上——**宇宙空間**まで。

**← リズムの変化: 短文で畳みかけ、改行で間を作る**

そこは24時間365日、太陽が沈むことのない世界。しかも大気による減衰がゼロ。
この「子供みたいな夢」を、JAXAやNASAが大真面目に実現しようとしています。

**← 感情の注入: 「子供みたいな夢」「大真面目に」で対比を演出**

[本文中略 — 二層構造・証拠パート・未来パートの実例は本書フルバージョンに掲載]

次のエネルギー革命は、地上ではなく、星の海からやってくるのかもしれません。
今夜、空を見上げたら——あの星々の間に、未来の発電所が浮かんでいることを、想像してみてください。

**← 最後の問い: 読者の意識を「未来」に飛ばして余韻を残す**

## 9.1 テーマ発掘プロンプト

```
■ カテゴリ配分:
  - 日常の謎（3件）: 当たり前を「なぜ？」に
  - テック深掘り（4件）: バズワードの中身を解剖
  - 社会×科学（3件）: 噂を科学で検証

■ 各テーマに以下を添えて：
  1. 一行Hook（「えっ？」を引き出す一文）
  2. よくある誤解
  3. 図解にしやすいか（Yes/No + 理由）
  4. 推定需要（検索ボリュームの推定）

■ 除外テーマ: [過去に扱ったテーマリスト]
```

## 9.2 Evidence Pack作成プロンプト

```
テーマ「[テーマ名]」について、以下の構成でEvidence Packを作成してください。

■ 調査ルール:
  - 一次資料（論文、公式発表、政府報告書）を優先
  - 重要主張は2ソース以上で交差検証
  - 全情報にFact / Model / Hypothesisラベルを付与
  - 数値には必ず単位と前提条件を明記

■ 構成:
  1. 要点3行（Factのみ）
  2. 用語辞書（初心者向け。用語 | 説明 | 身近な例え）
  3. 仕組みの流れ（入力→変換→出力のフローチャート）
  4. 誤解ポイント（よくある誤解 | 正確な理解 | ソース）
  5. 数値・条件（値 | 単位 | 前提 | ソース）
  6. 限界・例外
  7. Hook候補（5パターン以上: 数値衝撃/逆説/質問/断言/比喩/告白）
  8. 比喩候補（比喩 | 実際の仕組み | 比喩の限界）
  9. 出典テーブル（主張 | URL | 信頼度: 一次/二次/三次）
```

## 9.3 記事執筆プロンプト

```
以下のEvidence Packから科学記事を書いてください。

■ 記事構成（Story Spine）:
  - Hook（400字）: 読者の常識を揺さぶる
  - なぜ？（500字）: 構造的原因をえぐる
  - 仕組み（600字）: 技術メカニズム。二層構造（直感→理屈）必須
  - 証拠（300字）: 数値データ。身近な単位に「翻訳」必須

  - 感情を入れる: 驚き、疑問、期待を正直に表現
  - 専門用語は初出で必ず補足

```

# おわりに ── AIは「代筆者」ではなく「相棒」

本書を通じて繰り返し強調してきたことがあります。

**AIは科学ライティングの「全自動化ツール」ではない。**

AIは驚異的な速度でドラフトを作り、パターンを提案し、情報を構造化してくれます。しかし、「この情報は本当に正しいか？」「この比喩は正確か？」「この断定は強すぎないか？」——これらの判断は、依然として人間の仕事です。

AIを「代筆者」として使えば、「AIっぽい」量産記事にしかなりません。
AIを「相棒」として使えば、一人では到達できなかった高みに行ける。

本書のメソッドが、あなたの科学ライティングを変えるきっかけになれば、これ以上嬉しいことはありません。

あなたが次に書く科学記事は、何のテーマにしますか？
